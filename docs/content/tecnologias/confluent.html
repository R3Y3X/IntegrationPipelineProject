La Tríada Tecnológica

Confluent Cloud no es solo "Kafka hospedado". Es una plataforma SaaS enterprise que integra tres pilares tecnológicos bajo un framework unificado de gobernanza y seguridad:

Apache Kafka

Event Streaming Core

El motor pub/sub distribuido que actúa como el sistema nervioso central de la plataforma. Ingiere y distribuye eventos a escala de Terabytes con latencia de milisegundos, sobre el Kora Engine propio de Confluent — optimizado para desacoplar compute de storage con Tiered Storage multinivel.

  • Tópicos con retención configurable: horas, días o infinita
  • Compactación por clave: mantiene el último estado de cada entidad
  • Particionamiento para procesamiento paralelo masivo
  • 120+ conectores fully managed: PostgreSQL CDC, Snowflake, S3, Salesforce…
  • SLA 99.99% con balanceo automático de particiones y réplicas
Uso en el bootcamp
La VM generadora de transacciones publica eventos en un tópico Kafka. Tu pipeline de StreamSets consume desde ese tópico en tiempo real.

Apache Flink

Stream Processing

Motor de procesamiento distribuido stateful en tiempo real. Permite filtrar, transformar, agregar y unir datos en movimiento usando Flink SQL declarativo — sin necesidad de escribir código Java o Scala. Mantiene estado entre eventos para detectar patrones complejos.

  • Ventanas TUMBLE: agregaciones en intervalos fijos (ej: cada 5 min)
  • Ventanas HOP: ventanas deslizantes solapadas para tendencias
  • Ventanas SESSION: agrupación dinámica por inactividad del usuario
  • Joins entre streams: unir transacciones con perfiles de cliente en tiempo real
  • Detección de patrones: N operaciones del mismo cliente en <10 minutos
Uso en el bootcamp
IBM demostrará Flink SQL filtrando transacciones sospechosas y calculando totales por cliente en ventanas de tiempo — sin detener el flujo de datos.

Apache Iceberg

Open Table Lakehouse

Integración nativa vía Tableflow que expone los eventos de tópicos directamente como tablas abiertas en formato Iceberg. Une el mundo del streaming en tiempo real con los motores analíticos del Data Lakehouse — sin duplicar datos ni construir pipelines ETL adicionales.

  • El tópico Kafka es la tabla — sin movimiento de datos intermedio
  • Compatible con Snowflake, Databricks, AWS Athena, Apache Spark
  • Schema evolution nativa con compatibilidad hacia atrás
  • Elimina la necesidad de ETL batch nocturno para alimentar el Lakehouse
  • Consultas SQL analíticas sobre datos frescos de segundos de antigüedad
Caso de uso extendido
Los resultados de fraude procesados por tu pipeline pueden exponerse directamente a Snowflake o Databricks para análisis histórico — sin ETL adicional.

Conceptos de Kafka: tópicos, particiones y offsets

Un tópico es el canal nombrado donde los productores publican eventos y los consumidores se suscriben. Es análogo a una tabla en bases de datos relacionales, pero orientado a flujo continuo de eventos.

Tópico

Canal lógico donde se publican y almacenan eventos. Los productores escriben y los consumidores leen de forma independiente.

Partición

Unidad de almacenamiento y paralelismo. Cada tópico tiene N particiones; dentro de cada partición los mensajes están ordenados por offset.

Offset

Número secuencial único de cada mensaje dentro de una partición. Los consumers guardan su posición de lectura usando el offset.

Consumer group

Grupo de consumidores que cooperan para leer un tópico. Cada partición se asigna a un solo consumidor del grupo.

Broker

Servidor individual del clúster. Almacena particiones de tópicos y atiende solicitudes de producers y consumers.

Replication factor

Cantidad de copias de cada partición distribuidas en distintos brokers. Un factor de 3 garantiza tolerancia a fallos de hasta 2 brokers.

  • Clave (key): determina a qué partición va el mensaje y cómo se ordenan eventos relacionados.
  • Valor (value): contiene el evento serializado según el contrato de Schema Registry.
  • Retención: los tópicos pueden retener datos horas, días o indefinidamente según la política configurada.
  • Compactación: mantiene el último valor por clave, útil para tablas de estado (changelog).

Seguridad, gobernanza y trazabilidad

Los contratos de datos describen la estructura esperada, Schema Registry aplica compatibilidad y los permisos ACL limitan quién puede leer o escribir. Stream Lineage permite observar cómo un dato avanza entre tópicos y procesos.

La idea clave

Kafka transporta y conserva eventos; Flink los procesa; los contratos y el lineage hacen que el flujo pueda entenderse y gobernarse en producción.

Simulador de Schema Registry

Probá cómo el Schema Registry valida la evolución de esquemas. Definí el esquema actual (v1) y el nuevo (v2), seleccioná el modo de compatibilidad y comprobá si la evolución es válida.

Principio fundamental

Los tópicos de Kafka solo almacenan bytes. El Schema Registry garantiza que productores y consumidores hablen el mismo "idioma" al serializar y deserializar esos bytes, previniendo roturas silenciosas en producción.

BACKWARD: Podés actualizar los consumidores primero. Los campos eliminados deben tener default. Los nuevos campos también.
