Importación de N{N}_fraud_analyst

Descarga tu paquete ZIP, importa tu toolkit y tu agente, y consulta los resultados enmascarados de TransaccionesEvaluadas-N.

Contexto activo

Selecciona tu número en Inicio antes de copiar configuraciones.

Objetivo

Preparado por IBM

Conexión workshop_confluent en Orchestrate, paquete ZIP fraud-workshop-N.zip y API key de la instancia TechZone.

Tu tarea

Activar la CLI, importar N{N}_fraud_mcp y N{N}_fraud_analyst. Verificar que solo lee TransaccionesEvaluadas-N.

Prerequisito

Pipeline_N debe estar en ejecución y publicando mensajes Avro válidos. Si el tópico está vacío, el agente no tendrá datos que analizar.

Cómo encaja todo

Tres capas distintas. El tópico no aparece en la pantalla de Conexiones de Orchestrate.

CapaNombre (ej. N=3)Qué hace¿Quién lo prepara?
Conexión workshop_confluent Credenciales del clúster Confluent (bootstrap, API key, Schema Registry). Sin tópico. IBM (una sola vez)
Toolkit N{N}_fraud_mcp Cuatro tools MCP. Reciben topic_number como parámetro al ejecutarse. Tú (importas desde el ZIP)
Agente N{N}_fraud_analyst Siempre llama las tools con topic_number="{N}" → TransaccionesEvaluadas-N. Tú (importas desde el ZIP)

Flujo al hacer una pregunta

Chat → agente N{N}_fraud_analyst → tool get_fraud_summary(topic_number="N") → MCP usa workshop_confluent para autenticarse en Kafka → lee TransaccionesEvaluadas-N.

Bloque 0 — Descargar tu paquete

  1. Confirma tu número N en Inicio.
  2. Descarga tu paquete con el botón de abajo. El archivo corresponde a tu número N seleccionado.
  3. Descomprime y abre una terminal dentro de la carpeta (deben verse toolkit-spec-N.yaml, agent-spec-N.yaml y la carpeta tools/).

Bloque 1 — Preparar la CLI

Paso 1 — Ambiente virtual

Desde la carpeta descomprimida del ZIP:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install ibm-watsonx-orchestrate
pip install -r tools/requirements.txt
orchestrate --version

En Windows PowerShell, activa el ambiente con .venv\Scripts\Activate.ps1.

Paso 2 — Activar instancia TechZone

La conexión workshop_confluent ya existe en Orchestrate. Solo necesitas activar la CLI con la URL y la API key de la instancia.

orchestrate env add \
  --name workshop \
  --url <URL_INSTANCIA_ORCHESTRATE>

orchestrate env activate workshop \
  --api-key <API_KEY_ORCHESTRATE>

Si el ambiente workshop ya existe, ejecuta únicamente env activate.

No guardes el secreto

No pegues la API key en el YAML del agente, el repositorio ni una captura.

Bloque 2 — Importar toolkit y agente

Resumen del bloque

  1. Importa tu toolkit con --app-id workshop_confluent (conexión ya creada por IBM).
  2. Importa tu agente (sin --app-id).
  3. Tu agente fija topic_number="{N}" en cada llamada — el tópico no va en Conexiones.

Paso 3 — Toolkit MCP

orchestrate toolkits import \
  --file toolkit-spec-N.yaml \
  --app-id workshop_confluent

orchestrate toolkits list

En la lista debe aparecer N{N}_fraud_mcp con las cuatro tools.

Paso 4 — Agente

orchestrate agents import --file agent-spec-N.yaml
orchestrate agents list

Confirma que aparece N{N}_fraud_analyst.

Tools del agente
ToolUso
get_fraud_summaryConteos, montos y top riesgo (topic_number fijado por el agente).
get_suspicious_transactionsLista alertas ordenadas por score.
get_transaction_detailInvestiga una transacción específica.
get_customer_activityResume la actividad reciente de un cliente.

Bloque 3 — Probar en UI

Paso 5 — Activar el agente

  1. Abre la instancia de watsonx Orchestrate en el navegador.
  2. Busca N{N}_fraud_analyst.
  3. Comprueba que las cuatro tools estén asociadas.
  4. Activa o despliega el agente y abre su chat de prueba.

Paso 6 — Consultas de prueba

Ejecuta estas preguntas en orden. Haz clic para copiar:

Resumen

“Dame un resumen de las transacciones evaluadas y los casos de mayor riesgo.”

Alertas

“Muéstrame las transacciones sospechosas y fraudulentas ordenadas por score.”

Explicación

“Explícame por qué la transacción con mayor riesgo fue clasificada de esa forma.”

Cliente

“Resume la actividad reciente del cliente con más alertas.”

Paso 7 — Validar aislamiento y masking

  • El diagnóstico indica TransaccionesEvaluadas-N.
  • El agente no permite solicitar otro número de tópico.
  • El nombre del cliente no aparece en claro.
  • El correo conserva solo la parte permitida por la máscara.
  • La tarjeta muestra únicamente los últimos cuatro caracteres.

Si aparece PII en claro

No la repitas ni la copies. Detén la prueba y revisa Field Masker en Pipeline_N antes de continuar.

Problemas frecuentes

ProblemaAcción
La CLI no reconoce orchestrateActiva .venv y repite la instalación dentro del ambiente.
Error al activar el ambienteConfirma que utilizas la URL completa de la instancia y su API key de Orchestrate.
Toolkit sin toolsReimporta toolkit-spec-N.yaml con --app-id workshop_confluent.
Agente sin datosComprueba que Pipeline_N está activo y que el tópico tiene offsets recientes.
Decode errorsCorrige la serialización Avro del Kafka Producer y valida con mensajes nuevos.
Datos de otro participanteDesactiva el agente y avisa al facilitador.

Laboratorio completado

Terminaste cuando el flujo completo funciona con tu mismo número N y el agente responde con datos evaluados y enmascarados.
