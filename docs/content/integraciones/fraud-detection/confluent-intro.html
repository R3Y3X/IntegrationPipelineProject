¿Qué es Confluent Cloud?

Antes de entrar al laboratorio, entendé la plataforma que vas a usar: qué es Confluent Cloud, por qué existe, cómo se diferencia del Kafka open source, y cuáles son los tres pilares tecnológicos que la componen.

¿Por qué Event Streaming?

"¿Cruzarías una calle transitada basándote en una foto de los autos que pasaron ayer?"

La mayoría de las empresas toman decisiones críticas con reportes nocturnos o batch. El problema no es de volumen — es de velocidad de reacción.

El reporte llega mañana

La decisión estratégica se toma cuando la oportunidad ya pasó.

El fraude no se detectó a tiempo

La transacción maliciosa se analiza horas después de procesada.

El cliente ya se fue

La oferta personalizada llega cuando el usuario ya cerró la app.

Batch tradicional

Decisiones tardías

  • Datos procesados cada N horas o 1 vez al día
  • Ventanas de fraude amplias — horas de exposición
  • Inventarios desincronizados entre canales
  • Pipelines ETL frágiles y costosos de mantener
Event Streaming con Confluent

Tiempo real

  • Eventos procesados en milisegundos desde el origen
  • Detección de fraude antes de aprobar la transacción
  • Inventarios sincronizados en todos los canales
  • 120+ conectores managed sin código ETL

¿Con cuál de estos escenarios te identificás?

Perfil A — Negocio / Tecnología

Tus sistemas no reaccionan a tiempo y los reportes siempre llegan tarde

No necesariamente sabés qué es Kafka. Lo que sí sabés es que tus procesos tienen lag: los reportes llegan tarde, las alertas de fraude se activan cuando el daño ya está hecho, y tus equipos trabajan con datos del pasado para tomar decisiones del presente.

Confluent resuelve el problema de arquitectura que está detrás de todo eso — sin que tengas que cambiar tus aplicaciones de un día para el otro.

Perfil B — Ingeniería de Datos

Ya usás Apache Kafka y tu equipo dedica más tiempo a operarlo que a construir valor

Sabés muy bien qué es Kafka. El problema es lo que lo rodea: parches de versión, rebalanceo de particiones, monitoreo de brokers, ausencia de Schema Registry nativo, sin RBAC centralizado. El equipo de datos terminó siendo el equipo de operaciones de Kafka.

Confluent Cloud es la misma base técnica que ya conocés, pero con toda la carga operativa gestionada como SaaS — con SLA 99.99% y gobernanza enterprise incluida.

La Tríada Tecnológica

Confluent Cloud no es solo "Kafka hospedado". Es una plataforma SaaS enterprise que integra tres pilares tecnológicos bajo un framework unificado de gobernanza y seguridad:

Apache Kafka

Event Streaming Core

El motor pub/sub distribuido que actúa como el sistema nervioso central de la plataforma. Ingiere y distribuye eventos a escala de Terabytes con latencia de milisegundos, sobre el Kora Engine propio de Confluent — optimizado para desacoplar compute de storage con Tiered Storage multinivel.

  • Tópicos con retención configurable: horas, días o infinita
  • Compactación por clave: mantiene el último estado de cada entidad
  • Particionamiento para procesamiento paralelo masivo
  • 120+ conectores fully managed: PostgreSQL CDC, Snowflake, S3, Salesforce…
  • SLA 99.99% con balanceo automático de particiones y réplicas
En este bootcamp La VM generadora de transacciones publica eventos en un tópico Kafka. Tu pipeline de StreamSets consume desde ese tópico en tiempo real.

Apache Flink

Stream Processing

Motor de procesamiento distribuido stateful en tiempo real. Permite filtrar, transformar, agregar y unir datos en movimiento usando Flink SQL declarativo — sin necesidad de escribir código Java o Scala. Mantiene estado entre eventos para detectar patrones complejos.

  • Ventanas TUMBLE: agregaciones en intervalos fijos (ej: cada 5 min)
  • Ventanas HOP: ventanas deslizantes solapadas para tendencias
  • Ventanas SESSION: agrupación dinámica por inactividad del usuario
  • Joins entre streams: unir transacciones con perfiles de cliente en tiempo real
  • Detección de patrones: N operaciones del mismo cliente en <10 minutos
En este bootcamp IBM demostrará Flink SQL filtrando transacciones sospechosas y calculando totales por cliente en ventanas de tiempo — sin detener el flujo de datos.

Apache Iceberg

Open Table Lakehouse

Integración nativa vía Tableflow que expone los eventos de tópicos directamente como tablas abiertas en formato Iceberg. Une el mundo del streaming en tiempo real con los motores analíticos del Data Lakehouse — sin duplicar datos ni construir pipelines ETL adicionales.

  • El tópico Kafka es la tabla — sin movimiento de datos intermedio
  • Compatible con Snowflake, Databricks, AWS Athena, Apache Spark
  • Schema evolution nativa con compatibilidad hacia atrás
  • Elimina la necesidad de ETL batch nocturno para alimentar el Lakehouse
  • Consultas SQL analíticas sobre datos frescos de segundos de antigüedad
Caso de uso extendido Los resultados de fraude procesados por tu pipeline pueden exponerse directamente a Snowflake o Databricks para análisis histórico — sin ETL adicional.

Tipos de Cluster en Confluent Cloud

Confluent ofrece cuatro perfiles de clúster según el caso de uso. En este bootcamp usamos un clúster compartido de tipo Standard, resaltado a continuación:

Basic

Dev / POC

  • Sin costo fijo por hora
  • Sin SLA garantizado
  • Single-zone
  • Ideal para prototipos y pruebas

Standard ← este bootcamp

Producción ligera / media

  • Storage ilimitado (Tiered Storage)
  • Escalamiento elástico automático
  • Multi-zona, alta disponibilidad
  • Schema Registry incluido

Enterprise

Cargas críticas enterprise

  • Private Link / VNet peering
  • RBAC avanzado + Audit Logs completos
  • SLA enterprise 99.99%
  • Soporte dedicado

Dedicated

Alto rendimiento / aislamiento total

  • MB/s dedicados y garantizados
  • VPC Peering / Transit Gateway
  • Aislamiento completo de red y compute
  • Ideal para regulaciones estrictas
